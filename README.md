# MenuQueue

Apple Musicをメニューバーから操作するmacOSアプリ。再生キューをドラッグで並べ替え、
ライブラリやプレイリストから曲を追加できます。

## 操作

操作部分はアイコン中心です。常時表示する文字は曲名・アーティスト・プレイリスト名と
曲数・時間に絞っています。各アイコンにマウスを置くと操作名を確認できます。

| アイコン | 操作 |
|---|---|
| リスト | 自分の再生キュー |
| ＋ | 曲の検索・プレイリストから追加 |
| 音符付きリスト | Music側の「次に再生」（読み取り専用） |
| ▶ / Ⅱ | 再生・一時停止 |
| ≫ / ≪ | 次の曲・前の曲 |
| シャッフル / リピート | キューの順番・繰り返し |
| 歯車 | 設定 |

- キューの▶で先頭から再生。曲をダブルクリックするとその曲へ移動します。
- 曲の順番はドラッグで変更できます。右クリックから再生・削除などを選べます。
- 曲の追加後はチェックマークで受け付けたことを表示します。
- 次へボタンは連続クリックを順番に処理し、処理中はインジケーターを表示します。
- Music自身で再生しているときの次へボタンはMusicの曲送りを使用します。
- メニューバーのアイコンを右クリックし「ウインドウで開く」を選ぶと常設表示できます。

## 動作環境・ビルド

macOS 14以降、Music.app、Xcode Command Line Toolsが必要です。
ビルドしたMacと同じCPU向け（Apple Silicon / Intel）のアプリを生成します。

```bash
./build.sh
open build/MenuQueue.app
```

インストールする場合は起動中のMenuQueueを終了してから:

```bash
mkdir -p ~/Applications
cp -R build/MenuQueue.app ~/Applications/
open ~/Applications/MenuQueue.app
```

設定の電源アイコンでログイン時起動を切り替えられます。
CLIではアプリの実行ファイルに `--register-login-item` / `--unregister-login-item` を指定します。
`--window` を付けると起動時に常設ウインドウを開きます。

## メニューバーパネルの位置

パネルはクリックした画面のメニューバー直下に開き、その画面の表示可能領域に収まります。
タブ選択や再生曲の更新で位置・サイズを変更しません。画面の左右端・負の座標・上下に並んだ
ディスプレイも扱います。画面構成が変わったら一度閉じ、次のクリック時に配置し直します。
画面外クリックまたはEscapeで閉じます。常設ウインドウは明示的に開いた場合だけ表示します。

## Musicとの連携

Music.appはAppleScriptに「次に再生」の編集APIを公開していないため、MenuQueueは
自分のキューを持ち、1曲ずつMusicへ渡します。ライブラリに追加していないプレイリスト内の
曲も、保存したプレイリストIDを使って探します。配信終了やサインイン状態により再生できない
場合は警告アイコンを表示します。

曲情報は列単位で一括取得し、500曲上限を設けていません。ローカル確認では271曲を全件取得しました。
検索はMusicのライブラリを対象にし、最大60件を表示します。

安定した曲送りを有効にすると、キュー再生中だけMusicのリピート1を借用します。
キューを空にする・キュー再生が終わる・アプリ終了時に元の設定へ戻します。
曲末4秒は100ms間隔で確認しますが、Musicやネットワークの応答時間に依存するため完全な
ギャップレス再生は保証しません。キューのリピート「すべて」「1曲」は別途適用されます。
再生済み削除が有効の場合、削除した曲はリピートしません。

シャッフルは現在の曲より後を並べ替えます。オフにすると未再生分の順番を復元し、
再生済みの曲を再びキューの先へ入れません。
キューは `~/Library/Application Support/MenuQueue/queue.json` に変更ごとにatomic書き込みします。

## 必要な許可

- **オートメーション**: Musicの状態取得・再生操作に使用します。
- **アクセシビリティ**: Music側の「次に再生」を読むときだけ使用します。

Music側のキューは更新アイコンを押したときだけ読み取ります。タブ選択ではMusicの画面を
操作しません。対象リストを特定できない場合は警告を表示し、他のライブラリ一覧で代用しません。
この読み取りはMusicのUI構造に依存し、OSの更新や表示状態によって利用できないことがあります。

ビルドはad-hoc署名です。再ビルドによりオートメーションやアクセシビリティの許可を
再度求められる場合があります。

## 検証

```bash
./build.sh  # AppleScript構文、Swiftコンパイル、署名
./test.sh   # Music再生を変更しない回帰テスト
```

テスト用Musicアダプターと一時ファイルで、キュー保存・シャッフル復元・曲送り競合・
連続クリック・再生失敗・リピート復元・複数ディスプレイ配置を検証します。
GitHub ActionsでもmacOS上のビルドと回帰テストを行います。

`Tests/MusicReadCheck.swift` は起動中のMusicから読み取りだけ行う実機確認用です。
曲数、プレイリストからの曲検索（再生無効）、再生状態の読み取りを検証します。
実際の音声再生・ログイン項目・アクセシビリティ許可は自動テストの対象外です。
