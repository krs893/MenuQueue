# MenuQueue

Apple Musicをメニューバーから操作するmacOSアプリです。
メニューバーは固定幅の音符アイコンのみ。曲名はパネル内に表示します。

## 画面

- **リストのアイコン**: Musicで現在再生しているキュー。
- **音符付きリスト**: プレイリスト一覧と曲の再生。

操作部分はアイコン中心。曲名・アーティスト・プレイリスト名・時間・曲数を表示し、
操作の説明はマウスを置いたときのヒントにしています。
プレイリスト内の曲は行全体を1クリックすると再生します。プレイリストの▶は全体再生、＋は全曲を現在のMusicキューに追加します。
追加はMusicの「キューに追加」を優先し、その項目がない場合は「次に再生」を使います。その場合は現在の曲の直後に追加されます。
Musicのネイティブメニューを利用するため、全体追加にもアクセシビリティの許可が必要です。
別の保存済みキューには切り替えません。再生・曲送り・シャッフル・リピートはMusicを操作します。
次へボタンは連続クリックを順番に処理します。
シャッフルの連打は最後のオン・オフにまとめ、Musicの応答待ちでも操作状態を保持します。

キューはMusicのアクセシビリティ情報を読み取ります。**初回はアクセシビリティの許可が必要です。**
必要に応じてMusicのキュー表示をバックグラウンドで開いて読み取り、元の開閉状態に戻します。
MusicのUI変更・最小化・表示状態によって読み取れない場合は警告アイコンを表示します。
「再生を続ける」などの区切りを認識し、履歴とセクション見出しを除き、次に再生される曲とAutoPlayの曲を表示します。更新アイコンで再取得できます。Musicの実際のキューは読み取り専用で、別の曲リストを代用しません。

パネルはクリックした画面のメニューバー直下に開き、その画面の表示可能領域に収まります。
タブ選択・曲名更新ではパネルの位置や幅を変更しません。画面外クリックかEscapeで閉じます。
メニューバーを右クリックして「ウインドウで開く」を選ぶと常設表示もできます。

## ビルド・インストール

macOS 14以降、Music.app、Xcode Command Line Toolsが必要です。
ビルドしたMacと同じCPU向け（Apple Silicon / Intel）に生成します。

```bash
./build.sh
open build/MenuQueue.app
```

インストールは起動中のMenuQueueを終了してから:

```bash
mkdir -p ~/Applications
cp -R build/MenuQueue.app ~/Applications/
open ~/Applications/MenuQueue.app
```

設定の電源アイコンでログイン時起動を切り替えられます。
実行ファイルに `--register-login-item` / `--unregister-login-item` を指定しても切り替えられます。
`--window` を付けると常設ウインドウを開きます。

Music操作にはオートメーション許可、キュー読み取りにはアクセシビリティ許可を使います。
ad-hoc署名なので再ビルドで再許可が必要になることがあります。

## 検証

```bash
./build.sh  # AppleScript構文、Swiftコンパイル、署名
./test.sh   # ユーザーのMusic再生を変えない回帰テスト
```

テスト用Musicアダプターで曲送り・シャッフルの連打、遅い応答、古い状態取得、失敗からの復旧、
プレイリスト全体追加と再生を混同しないこと、Musicへの直接再生、旧キューによる
操作の横取り防止を検証します。パネル配置は5種類のディスプレイ配置と左右端で検証します。
GitHub ActionsでもmacOSビルドと回帰テストを行います。

`Tests/MusicReadCheck.swift` はMusicから読み取るだけの実機確認用です。
実際の音声再生・アクセシビリティ経由のキュー表示・複数画面の実機動作は自動テストの対象外です。

旧版の独自キューの保存データとモデルは互換性のため残していますが、現在の画面からは使用しません。
ユーザーの保存済みデータは削除しません。

キュー取得の診断は `defaults read jp.local.menuqueue queueReadStatus` と `queueReadDate` で確認できます。件数またはエラーと時刻だけを保存し、曲名は保存しません。
